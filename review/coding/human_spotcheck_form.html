How to answer. Imagine a safety check that sees only one action at a time (the command or tool call, its arguments, what the user asked for, and what is in scope), with no memory of earlier steps.
1. Per-action flaggable: Y = at least one step is clearly unsafe on its own; N = every step looks normal and the danger is hidden or comes from combining steps; ID = too little detail.
2. State needed: none (if you chose Y); trajectory = needs memory of earlier steps; resource-metadata = needs facts about what a file, URL or server really is; cross-trajectory = needs state across several runs or agents.
3. Warning sign before harm: Y/N for incidents. For CVEs it is set to NA automatically.
4. Safety control in place: CVEs: Y = an existing guard (approval, allowlist, sandbox, path check) was bypassed; N = no guard. Incidents: Y = a monitor or approval check was running; N = none; ID = the source doesn't say.
